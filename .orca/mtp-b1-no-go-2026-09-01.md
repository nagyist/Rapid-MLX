## Design and route proof

The generic continuous planner keeps its batch-first minimum of two lanes.
Only an explicitly installed continuous integration is allowed to set
`min_batch_lanes=1`; ineligible sampling/cache/tool requests still fail open to
the mature path. This uses the same scheduler-owned proposal/commit/abort
contract as multi-lane continuous MTP instead of adding a second singleton
engine.

The candidate emitted this receipt for warmup and every measured request:

```text
[MTP-continuous] admitted continuous cohort route=continuous_planned lanes=1 draft_depth=2
```

The baseline emitted no one-lane continuous admission receipt and remained on
the existing adaptive singleton MTP verifier.

## Reproduction

The two servers ran sequentially with no other model resident. Both used the
same command and differed only by checkout:

```bash
HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 RAPID_MLX_PREFIX_CACHE_AUTOLOAD=0 \
python3.12 -m vllm_mlx.cli serve qwen3.8-27b-4bit \
  --host 127.0.0.1 --port 8482 \
  --max-num-seqs 4 --max-concurrent-requests 4 \
  --hybrid-cache-entries 0 --disable-prefix-cache --no-thinking \
  --force-spec-decode \
  --speculative-config \
  '{"method":"mtp","continuous_batching":true,"allow_dynamic_membership":false}'
```

The performance prompt contained 1,154 input tokens describing a fictional
40-module Python service and requested a concrete lifecycle refactor. Each run
used greedy sampling and a 256-token output budget. Prefix reuse was disabled.

## Performance

| Route | Run 1 | Run 2 | Run 3 | Median wall | Median output/wall |
| --- | ---: | ---: | ---: | ---: | ---: |
| Existing singleton MTP | 9.542 s | 9.239 s | 9.224 s | 9.239 s | 27.71 tok/s |
| Continuous B1 | 10.979 s | 10.900 s | 10.947 s | 10.947 s | 23.38 tok/s |

Continuous B1 increased median wall time by 18.5% and reduced end-to-end
output throughput by 15.6%. Peak active Metal memory was similar and therefore
does not explain or compensate for the regression.

## Correctness spot-check

Five additional greedy prompts covered Python coding, exact JSON, Chinese
reasoning, creative writing, and concise chat. All five candidate outputs were
byte-identical to baseline, so B1 introduced no output regression in this
panel. Absolute task quality was mixed and must not be overstated: JSON parsed
and matched every requested value but was pretty-printed rather than compact;
the coding answer hit its 192-token budget before the requested asserts; and
both routes incorrectly answered 17 seconds for `12 + max(8, 5) + 3`, whose
correct total is 23 seconds. Creative output contained exactly four sentences
and chat returned four bullets.

The longer 256-token engineering output was deterministic within each route
but differed between routes at a close numerical boundary. Both versions were
coherent and truncated at the requested budget. The performance regression is
the blocking result regardless of that acceptable semantic outcome.

## Local contracts

The isolated implementation plus the current-main compatibility adjustment
passed 243 focused scheduler, routing, transaction, generation-batch,
qualification, engine, and MLX-backend tests. Ruff check, Ruff format, and
`git diff --check` passed.

## Decision

NO-GO for production, defaults, or a PR. Retain the existing singleton MTP
verifier. Revisit only if a later kernel/backend change makes B1 cheaper than
the same-version singleton route under this exact paired method.
